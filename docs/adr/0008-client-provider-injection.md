# ADR-0008: L2 Redis 客户端以提供者函数注入（ClientProvider）

- 状态：已接受
- 日期：2026-11-17

## 背景

L2 的 Redis 客户端有几种注入形态：

1. 业务构造实例后传入（库持有生命周期）；
2. 提供者函数注入：库每次 L2 操作时向提供者索取当前可用客户端。

Redis 运维场景存在实例更替（故障切换、配置变更），若库持有固定实例，更替需要重启进程或库感知重建逻辑；Pub/Sub 订阅也与客户端实例绑定。库希望进程内状态（世代号缓存、负缓存、singleflight、L1）与客户端实例生命周期解耦。

## 决策

Redis 客户端以**提供者函数**注入，库不持有实例的创建与生命周期：

```go
// 提供者契约：返回当前可用的客户端实例（返回即已连接就绪）
type ClientProvider func(ctx context.Context) (RedisCmdable, error)
```

- **每次 L2 操作原子获取当前客户端**，操作间不保证同一实例——缓存单操作幂等，正确性由世代号与 TTL 兜底，不依赖请求级实例一致性；
- **返回即可用契约**：提供者返回的实例必须已连接就绪（失败应返回 error 而非不可用实例）；持续返回同一实例合法；
- **请求级实例配对**非库的职责，需要时由提供者实现方自行保证；
- **Pub/Sub 订阅与客户端实例绑定**：适配器检测到实例变更后以新实例重建订阅；重建窗口内丢失的事件由世代号短 TTL 惰性刷新兜底（ADR-0002）；
- 进程内状态不依赖具体客户端实例，实例更替对其透明。

## 备选方案

- **构造时传入固定实例**：库需感知实例更替或依赖业务重启，Pub/Sub 重建逻辑复杂。被否决。
- **库内置连接管理/重连**：违背轻量定位，且运维策略（哨兵/代理/自管）属于业务环境。被否决。

## 后果

- 单机/集群/代理等部署形态经提供者统一接入（`RedisCmdable` 抽象）。
- 实例更替期间个别操作可能短暂失败，由定义级降级策略（`SourceOnly` / `StaleL1` / `Fail`）处理。
- 提供者实现质量（返回可用实例）成为业务侧责任，库以契约约束并报错而非静默降级。
