# ADR-0005: 跨实例 L1 一致性采用事件驱动失效广播，事件不携带 value 载荷

- 状态：已接受
- 日期：2026-11-17

## 背景

L1 为各实例独立的本地缓存，跨实例一致性需要一个同步机制。可选方向：

1. **事件广播 + 删除**：写实例发布 `Updated`/`Invalidated` 事件，订阅方删除各自 L1 对应条目，下次读走 L2 拿新值。
2. **事件携带新值**：订阅方直接用事件中的 value 更新 L1。
3. **强一致协议**（分布式共识/租约）：复杂度远超本库定位。

事件语义与发起实例自身的行为也有细节要定：发起 `InvalidateAll` 的实例不能等自己的事件（Pub/Sub at-most-once 且异步），否则自身 L1 短暂不一致。

## 决策

采用事件驱动失效广播：

- 订阅方收到 `Updated/Invalidated` 后**删除**各自 L1 对应条目（不回源、不更新），删除后下次读走 L2 即新值；
- **事件不带 value 载荷**（大值不经 Pub/Sub，与轻量定位一致）；
- 收到 `GenerationBumped` 后整代 L1 清空（`Keys` 为空，订阅方按 `DefName` 清空）；
- 发起 `InvalidateAll` 的实例不依赖自身事件：`INCR` 成功后同步清空自身 L1 并更新本地世代号；`Instance` 过滤仅作用于 `Updated/Invalidated`；
- 订阅方由库将事件中的变换后物理 key **逆变换**映射回逻辑键后删 L1；
- 事件保证 at-most-once，L1 一致性定位为"最终、秒级"，不承诺强一致；丢事件的兜底为世代号短 TTL 惰性刷新（ADR-0002）。

## 备选方案

- **事件携带 value**：大值经 Pub/Sub 传输违背轻量定位，且 Pub/Sub 无持久化、消息体积放大。被否决。
- **订阅方收到事件即回源**：回源风暴风险。被否决（删除后惰性回源）。

## 后果

- 事件轻量（仅 key 列表），Pub/Sub 载荷可控。
- 一致性为最终一致、秒级窗口；需要更强一致的业务须自行在写侧组合（如规划中的 `DeleteTwice`）。
- `GenerationBumped` 一次事件即清理整代 L1，与世代号机制（ADR-0002）天然配合。
